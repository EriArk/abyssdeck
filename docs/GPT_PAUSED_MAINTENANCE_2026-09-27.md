# Остановленная отправка и допуск к обновлению

## Причина

Проверка обновления считала любой `gpt_jobs.status=unknown` активной работой.
У старой нативной отправки были одновременно `NATIVE_CHAT_PAUSED`, `paused=1`,
три неудачных подтверждения и сохранённая квитанция. Рабочий процесс уже
прекратил проверки, однако maintenance бесконечно ожидал эту запись.

Чтение состояния нативного приложения подтвердило `idle` для соответствующего
чата и остальных возвращённых GPT-чатов. Это свидетельство отсутствия текущей
работы, **не** доказательство доставки старого сообщения. Квитанция остаётся
неопределённой; её текст, частичный ответ и привязки не переписываются.

## Исправление

`bcbd2f5` исключает из активной работы Hub только сочетание всех признаков:
нативный provider, `unknown`, точная ошибка `NATIVE_CHAT_PAUSED`, сохранённая
квитанция и долговечная пауза после минимум трёх неудач. Отсутствующие таблицы,
неполное подтверждение паузы, обычные `unknown`, preparing/running/queued и
остальные операции продолжают блокировать обновление.

Перезапуск Hub не возобновляет проверки такой записи и не отправляет сообщение.
Перезапуск отдельного нативного процесса требует независимого допуска: пауза
Hub сама по себе не означает, что нативная генерация закончилась.

## Проверки и переход со старой версии

- 26 целевых тестов: классификация, неполные доказательства, сохранность записей
  после перезапуска worker, изоляция отправок и существующий doctor admission.
- TypeScript, чистая сборка релиза и проверка репозитория прошли.
- Проверка нового образа: авторизация, внутренний сокет, Team, PWA и обычные API.
  UI не менялся; прежние браузерные результаты не выдаются за новый прогон.
- Старый Hub `d6933eb` не мог применить исправление собственного классификатора.
  Для этого единственного перехода использована приватная проверка нового кода:
  все namespaces без активных блокировок, ровно одна подтверждённая пауза,
  агрегатная работа старого Team точно равна ей. Перед финальным допуском закрыт
  публичный gateway и зарезервированы персональные терминалы. Обычные блокировки
  развёртывания, холодная копия, проверка восстановления и rollback сохранены.
  Force-флаг и переписывание исходов отправок не использовались.
- Нативный owner-адаптер `338ef6a` установлен отдельно под manual lease после
  проверки `idle`. Создана холодная резервная копия, сверены все строки базы
  нативных квитанций до/после, доступны `independentReads` и `historyUpdates`.

- Hub `bcbd2f5` установлен; его обычный maintenance-check после завершения
  запросов возвращает `idle: true`, без блокировок. Приёмочная проверка API
  подтвердила healthy/canSend и HTTP 200 для моделей, каталога и deployment.
  Тест не требует отсутствия любой кратковременной работы одновременно с чтениями.
- Member-образ `338ef6a` и шаблон provisioning обновлены. Профиль этого участника
  ещё без binding: его вход не выполнялся и не считается проверенным.
- Хеши 32 файлов обоих работающих нативных адаптеров совпали с исходниками.
  Строки старой отправки, квитанции и read-health после установки Hub совпали с
  холодной копией. Тестовых сообщений в реальные чаты не отправляли.

Итоговое состояние установки и оставшаяся приёмка — в [CURRENT_STATUS.md](CURRENT_STATUS.md).
