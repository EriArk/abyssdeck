## Поведение

- Лупа в Results обоих клиентов открывает отдельный поиск файлов/изображений.
  Область — точный чат либо проектная лента Codex. Поиск имени/расширения,
  тип, порядок новые/старые/имя и продолжение за пределами загруженной ленты.
- Подробный поиск содержимого теперь включает названия Results выбранного
  GPT-чата; фильтр «Файлы» доступен и там. Сообщения и результаты сохраняют
  разные точные цели. Смена ветки сбрасывает несовместимое продолжение.
- Имя найденного файла открывает общий просмотрщик поверх сохранённого поиска;
  отдельная кнопка показывает карточку в ленте. Закрытие сохраняет запрос,
  фильтры, порядок, прокрутку и черновик основного чата.
- Предыдущий/следующий файл листают загруженную подборку внутри одного окна.
  Свойства и разворот окна сохраняются; старые байты не получают имя нового файла.
  «К сообщению» открывает точный источник при наличии его идентификатора.
- Фокус на карточке исполняется один раз на явный переход, только внутри
  Results. Раньше зависимость эффекта от обновляемого массива снова вызывала
  `scrollIntoView(center)` при каждом обновлении. Теперь фоновое обновление
  не повторяет этот скачок. Исправлено также исчезновение найденной карточки
  при автоматическом выборе другой категории.
- Окно поиска и отдельный ряд навигации просмотрщика используют материалы темы,
  защищённый заголовок, симметричные поля и независимую прокрутку.

## Границы реализации

`result-search.ts` отдаёт только id/title/type/date/thread/turn metadata: без
payload, локальных путей, URL или чтения бинарных файлов. Одна страница сканирует
до 500 подходящих записей и возвращает до 40 совпадений. В UI — до 200 совпадений,
после чего уточняется запрос; это бюджет выдачи, не ограничение файлов.

Codex продолжает по rowid либо паре нормализованное имя/rowid с фиксированным
верхним rowid. Вставки после начала поиска не сдвигают страницы. Курсор привязан
к точной области, запросу, типу и сортировке. GPT использует существующий индекс
публичных результатов, курсор дополнительно связан с ревизией. Никакого обхода
каталога GPT, нового native writer или повторения отправок нет. Точное открытие
снова проверяет существующий авторизованный источник. Одинаковые имена не
склеиваются: отдельные результаты сохраняют разные id.

Поиск не читает содержимое документов, соседние файлы ограничены загруженной
подборкой. Схема SQLite и Windows helper/native GPT контракты не меняются.
Все сохранения используют прежний DownloadLink, редактор — прежнюю явную копию.

## Проверки

- 16 целевых тестов: новый `result-search.test.mjs`, `content-search.test.mjs`
  и регрессия `gpt-incremental.test.mjs`. Реальные Hub routes, два частных

  пустая промежуточная выдача, несовместимая ревизия, отсутствие payload.
- Chromium и WebKit: страницы/сортировка/отмена устаревшего запроса, пересборка
  выдачи при новой ревизии, последовательное открытие с точными байтами,
  свойства окна, возврат к запросу и scroll, источник, карточка за первой
  страницей, отсутствие повторного focus-scroll, сохранение черновика, ноль
  mutation-запросов. Оба клиента используют один компонент.
- Проверены четыре темы, телефон, высота с клавиатурой, планшет и широкий
  экран. Реальные скриншоты просмотрены; исправлены обнаруженные смещение
  мобильного окна и слабый контраст подписи на корпусе hitech.

Физическая iPhone/iPad приёмка остаётся за обычным использованием владельца;
браузерная фикстура не означает её завершения. Активация фиксируется отдельно
в CURRENT_STATUS после проверки установленной версии.
