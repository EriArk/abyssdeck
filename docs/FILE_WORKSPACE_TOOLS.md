# Единое окно файла: просмотр, правка и инструменты

Обновлено 3 октября 2026. Владелец одобрил корпус просмотрщика и уточнил:
редактор открывается **в том же окне**, возможности сохраняются и расширяются;
Markdown и изображения — примеры, инструменты подбираются для всех форматов,
где они полезны. Общий корпус и встраиваемый текстовый редактор внедрены в исходники;
установленная версия указана в `CURRENT_STATUS.md`. Контекстные инструменты второго
этапа перечислены ниже; остальная карта остаётся направлением расширения.

## Поведение окна

- Имя, источник, геометрия, док, тема и положение окна не меняются при переходе.
  Кнопка правки включает режим и раскрывает подходящий компактный ряд инструментов.
  Просмотр и правка показывают один текущий документ, включая несохранённые изменения.
- «Просмотр» не означает отмену или сохранение. Курсор, выделение, Undo/Redo,
  черновик и позиция остаются при возврате к правке. Для документов сохраняется
  страница, для изображений — область/масштаб, для книг — позиция в тексте.
- Инструменты принадлежат формату и активному режиму. Общие действия — источник,
  свойства, сохранение, отправка. Не показывать карандаш там, где нет настоящего
  поддерживаемого способа правки. Разметку называть разметкой, а не правкой текста PDF.
- Полоса инструментов компактная, с группами по назначению, понятными иконками,
  доступными названиями и пояснениями. Редкие параметры открываются по месту.
  На телефоне отдельный второй ряд вместо уменьшения кнопок; без постоянной панели
  всех инструментов всех форматов. Переход краткий, без смены корпуса и с reduced motion.
- Стрелки подборки не выбрасывают черновик предыдущего файла. Состояние хранится
  по точному источнику и версии, не по имени. При явном закрытии изменённого файла
  сохраняются существующие варианты сохранить, оставить черновик, отменить изменения.
  Сворачивание в док сохраняет всё смонтированным.

## Проверенная карта форматов и целевые инструменты

«Сейчас» ниже проверено по исходному коду; не означает тест на физическом устройстве.
«Расширить» — целевой набор, а не уже действующие функции. Ни один существующий
обработчик не удаляется ради общей панели.

| Формат | Сейчас — сохранить | Расширить по назначению | Правка и сохранение |
| --- | --- | --- | --- |
| PNG, JPEG, WebP, AVIF, GIF | Масштаб, панорамирование, вписать, фон прозрачности | Маркер, перо, стрелка, рамка, подпись; цвет/толщина, Undo/Redo; поворот и обрезка | Неразрушающий слой пометок, экспорт копии с явным форматом. Анимация GIF/APNG/WebP не превращается молча в один кадр; отдельная команда экспорта кадра. Оригинал и прозрачность сохраняются. |
| TXT, логи | Полное чтение, исходник, перенос, озвучивание; общий текстовый редактор | Поиск/замена, переход к строке, номера строк; сворачивание больших блоков где полезно | Тот же CodeMirror и существующие черновики/квитанции. Сохранять BOM и окончания строк; смешанные окончания не нормализовать молча. |
| Markdown | Читалка/исходник, озвучивание; подсветка в редакторе | Заголовок, жирный/курсив, список/задача, ссылка/изображение, цитата, код, таблица; оглавление | Инструмент применяет транзакцию к выделению, единый Undo. Предпросмотр текущего черновика в том же окне; расширенный split — только по запросу и регулируемый. |
| Код, JSON/JSONL, XML, YAML, TOML, INI/CFG, CSS, скрипты | CodeMirror, подсветка, поиск, Undo/Redo, перенос | Сворачивание блоков, переход к строке, парная скобка; для известных форматов проверка синтаксиса, затем явное форматирование | Текстовая правка без запуска кода. Форматирование отменяется и не происходит при открытии. JSONL проверяется построчно, не как один JSON. |
| HTML | Изолированный предпросмотр и текстовый исходник | Правка исходника, обновление предпросмотра черновика; размеры области просмотра | Предпросмотр в том же корпусе, с прежней изоляцией. Не превращать его в исполняемый доверенный интерфейс Hub. |
| PDF | Фиксированные страницы, переходы, масштаб | Поиск/выделение текста, миниатюры/оглавление; маркер, рукописные пометки, комментарии | Разметка по координатам страницы и экспорт копии. Полноценная правка существующего текста — отдельная возможность, не свойство текущего canvas-рендера. Не растрировать весь PDF молча. |
| DOCX | Серверная подготовка страниц PDF и фиксированный просмотр; оригинальный DOCX скачивается отдельно | Поиск/оглавление; рецензирование/пометки по страницам. Затем настоящий редактор абзацев, стилей, списков, таблиц и изображений | Изменение текста только с движком, сохраняющим структуру DOCX и проверяемый круг сохранения/открытия. Размеченная PDF-копия не выдаётся за изменённый Word-файл. |
| XLSX | Листы, размер текста, поиск, постраничная таблица, значения и просмотр формул | Выбор диапазона, копирование ячеек, закрепление шапки, фильтр/сортировка; затем значения/формулы/форматы, строки/столбцы | Нужен полноценный путь записи книги с сохранением остальных листов, формул и типов. Не выдавать текущий extractor за spreadsheet-редактор; не заменять книгу CSV при обычном сохранении. |
| CSV/TSV | Точное текстовое редактирование и исходные байты | Табличный режим, разделитель/кавычки, шапка, поиск, фильтр; правка ячеек | Сохранять разделитель, кавычки, переносы внутри ячеек, кодировку/окончания строк. Фильтр просмотра не удаляет скрытые строки при сохранении. |
| EPUB/FB2 | Книжные страницы, настройки чтения, позиционная озвучка и автопереход | Поиск, закладки, выделения и заметки с привязкой к фрагменту | Личные пометки отдельно от оригинальной книги. Редактор структуры EPUB/FB2 — самостоятельное расширение после проверки сохранности оглавления, изображений и метаданных. |
| ZIP | Навигация папок, поиск, список, извлечение/просмотр отдельного файла, общее сохранение | Множественный выбор и извлечение в выбранную папку; понятные размеры | Извлечение через общий файловый процесс и выбор коллизий. Перепаковка/изменение архива только отдельной явной операцией, не побочный эффект правки извлечённой копии. |
| SVG | Безопасный векторный просмотр, масштаб/фон; текстовая правка при поддержке редактором | Исходник и живой безопасный предпросмотр; цвет/геометрия выделенного элемента — последующее расширение | Сохранять SVG векторным. Растровая пометка на снимке — отдельная PNG-копия, не «сохранение SVG». |
| DXF | Масштаб/перемещение, слои, монохром/усиление линий, измерение, привязки и направляющие | Координаты/единицы, пометки для обсуждения, снимок вида | Точные размеры и заметки не называются CAD-редактированием; не менять геометрию через декоративную ручку. Сохранение оригинала отдельно от снимка/пометок. |
| STL, OBJ, 3MF, GLTF/GLB, STEP/IGES | Вращение/масштаб, проекции, сетка, габариты/единицы, существующая конвертация STEP/IGES для просмотра | Выбор объекта, измерение, сечение, снимок вида; пометки к выбранному виду | Не считать просмотренную сетку обратимо редактируемым STEP. Геометрическое редактирование/конвертация — отдельный явный путь с указанием потерь. |
| MP3, WAV, OGG, M4A | Воспроизведение, громкость, перемотка браузерного проигрывателя | Скорость, точная позиция, A–B повтор, закладки/заметки по времени; выбор фрагмента | Обрезка/экспорт — после отдельного медиапайплайна, без скрытого перекодирования. Пока управление воспроизведением не выдаётся за монтаж. |
| MP4, WebM | Воспроизведение, громкость, перемотка, inline-видео | Скорость, кадр вперёд где позволяет декодер, снимок кадра с разметкой, A–B повтор, заметки по времени | Снимок с пометками сохраняется отдельно; обрезка ролика требует настоящего экспорта. Не обещать покадровую точность через произвольный seek HTMLVideoElement. |
| Неизвестные/неподдерживаемые | Метаданные, оригинал, системная отправка/скачивание | Только достоверные свойства; запуск подходящего приложения через существующее действие | Без фиктивного редактора. PowerPoint остаётся вне scope по прежнему решению владельца; исходник доступен. |

## Архитектура перехода

`FileViewerDialog` остаётся владельцем окна. Форматный адаптер предоставляет
контент, инструменты и поддерживаемые режимы: просмотр, текстовая/структурная правка,
разметка. Список режимов определяется возможностями, а не только расширением имени.
Текущий `FilePreview`/реестр сохраняет обработчики; общая оболочка не дублирует
пагинацию, озвучку, проигрыватель или парсер документов.

`FileEditor` переносит проверенную логику CodeMirror, конфликтов, BOM/переносов,
локальных черновиков и неопределённых квитанций во встраиваемую область. Смена режима
не создаёт новый dialog и не пересоздаёт редактор/Undo. Источники GitHub по-прежнему
используют проверку точного HEAD/SHA и существующий reviewSave; это не локальный файл.

Разметка хранит исходные байты отдельно от операций и привязки к версии/странице/
времени. Точки в координатах исходного содержимого, не CSS-пикселях экрана. Поворот,
обрезка и масштаб учитываются при вводе и экспорте. Экспорт не заменяет оригинал
без точного пути, проверки текущего fingerprint и явного действия пользователя.

Working-copy сохраняется по существующему источнику и capability; Results, вложения,
извлечённые файлы — копии с явным назначением. Все сохранения используют общий
DownloadLink/FileCopySave и существующие квитанции/коллизии. Рабочие чаты не блокируют
ручную правку; потерянный ответ не разрешает повторную запись новым id.

## Последовательность внедрения

1. **Реализовано:** общий корпус и встраиваемый редактор: все текущие входы/форматы, режимы без нового
   окна, сохранность инструментов/источника/позиции, компактные панели. Переносится
   функциональность, новые сложные редакторы не имитируются.
2. **Реализовано в исходниках:** контекстные инструменты: Markdown и код/структурный текст, неразрушающая разметка
   изображений, применимые улучшения навигации/чтения/медиа/архивов. Отдельно проверить
   пустой черновик, выделение, Undo, смену файлов и страницы с пометками.
3. **Реализовано в исходниках:** PDF-разметка и экспорт, табличный режим CSV/TSV. Проверить исходные байты,
   страницы/координаты, Unicode/кавычки/переносы и round-trip сохранения.
4. DOCX/XLSX-редакторы, книжная структура, CAD и медиамонтаж — самостоятельные
   адаптеры с проверкой сохранности, добавляемые в тот же корпус по готовности.

Это порядок реализации внутри общей функциональной карты, а не исключение остальных
форматов из продукта. Новые неподключённые инструменты не выставляются в production.

## Доказательства и границы первого шага

Общая оболочка использует прежние обработчики форматов, DownloadLink и сохранение
копий. CodeMirror встраивается через общий контекст: переключение в просмотр
текущего черновика не пересоздаёт редактор, выделение и Undo. Закрытие общего окна
проверяет несохранённые изменения; сворачивание сохраняет экземпляр. Рабочие файлы
сохраняются по точному пути, GitHub — через прежний review с HEAD/SHA, вложения —
как копии. Первым шагом новые форматные панели не добавлялись.

Chromium/WebKit: file-tools (конфликт, lost ACK, черновик, Undo, пустой документ,
сворачивание), manual-edit (копии, GitHub review/квитанции), file-preview (форматы,
точные байты, сохранение/отправка) и window-dock. Typecheck/build прошли.
[Снимки реализации](../polish/05-files/viewer-workspace/README.md) сняты из браузерных
фикстур, а не с физического iPad.

Исходники: `FileViewerDialog.tsx`, `ViewerEditButton.tsx`, `FileEditor.tsx`,
`FilePreview.tsx`, `filePreviewRegistry.ts`, `PdfFilePreview.tsx`,
`DocxFilePreview.tsx`, `PackageFilePreview.tsx`, `VectorFilePreview.tsx`,
`DxfFilePreview.tsx`, `ModelFilePreview.tsx` в `apps/web/src`.

В [эскизе](../polish/05-files/viewer-study/README.md) демонстрируются PNG/PDF/MD:
режимы в одном корпусе, локальная разметка, текстовые инструменты, Undo/Redo,
сохранение демонстрационного черновика при возврате. Реальные загрузка, парсинг,
экспорт и запись в этом макете отсутствуют. PDF — пример компоновки, Markdown
в режиме чтения — текст черновика, не полноценный Markdown-рендерер.

## Второй шаг: инструменты формата, 3 октября

Реализованы в общем окне, без отдельного редактора:

- Markdown: заголовок, жирный/курсив, список/задачи, цитата, ссылка/изображение,
  ограждённый блок кода и таблица. Одна отменяемая транзакция по выделению.
- Текст/код: переход к строке, сворачивание поддерживаемых синтаксических блоков,
  парная скобка. JSON/JSONL: проверка и явное форматирование с сохранением точных
  числовых лексем, строк и повторных ключей; XML/SVG/XHTML: проверка синтаксиса.
- Растры: маркер/перо/стрелка/рамка/подпись, цвет и толщина, Undo/Redo,
  поворот и обрезка в координатах исходного изображения, масштаб и панорамирование.
  Слой разметки и замороженная основа сохраняются отдельным локальным черновиком
  по источнику, имени и SHA-256 исходных байтов в хранилище текущего аккаунта.
  Экспорт PNG с прозрачностью либо JPEG с белым фоном через FileCopySave/DownloadLink.
  Анимация явно открывается как снимок кадра. Оригинал остаётся неизменным.
- Аудио/видео: скорость, переход к секунде, выбор A/B и повтор фрагмента.
  Это управление проигрывателем, не монтаж и не покадровый редактор.
- ZIP: сортировка по имени/размеру и общий несжатый размер; прежние поиск,
  вложенный просмотр и извлечение сохранены.

Проверки: `text-format-operations.test.mjs`, `format-tools.browser.mjs`,
`file-tools.browser.mjs`, `file-preview.browser.mjs`, `help-content.test.mjs`,
`file-media-policy.test.mjs`,
web typecheck/build. Chromium/WebKit: Undo и выделение Markdown, точность JSON,
разметка после поворота/масштаба/обрезки, реальные PNG/JPEG байты, прозрачность,
восстановление после перезагрузки и удаление черновика, неизменность оригинала,
ZIP-сортировка. Медиа A–B на настоящем WAV и жест двумя пальцами проверены
в Chromium. Windows Playwright WebKit не декодирует WAV/MP3 (ошибка 4);
проверка воспроизведения в нём не заявляется.
Четыре темы, телефон/планшет — браузерные фикстуры, не физический iPad.
[Снимки и описания](../polish/05-files/format-tools/README.md).

PDF-разметка/экспорт и табличный CSV/TSV реализованы третьим шагом ниже.
Книжные контроллеры/озвучка и существующие Office/CAD-обработчики сохранены;
новые оглавления Markdown, медиамонтаж, редакторы DOCX/XLSX и CAD пока не добавлены.

Политика веб-страницы разрешает локальные Blob только для медиа (`media-src`),
как ранее для картинок. Script/connect/object ограничения не расширяются.
Обновление gateway не заменяет движок и не перезапускает его работу.

Выпуск `2e16c88` установлен: manifest и CSP проверены через HTTP Hub, Engine/GPT
не перезапускались. Linux gateway-тесты подтвердили непрерывность ответов,
очереди, форм, терминалов и атомарный откат публикации. См. `CURRENT_STATUS.md`.

## Третий шаг: PDF и CSV/TSV, 3 октября

PDF получает режим разметки в текущем окне: перо, полупрозрачный маркер,
Unicode-комментарии, палитра и толщина, Undo/Redo, отдельный режим прокрутки.
Координаты хранятся в пространстве страницы PDF, включая CropBox и поворот.
Локальный черновик связан с аккаунтом, источником, именем и SHA-256 исходных байтов;
закрытие предлагает оставить или удалить его. Экспорт через FileCopySave/DownloadLink
создаёт отдельный PDF: исходные страницы/текст/ресурсы/существующие аннотации остаются,
рисунки добавляются векторными путями, комментарии — стандартными Text-аннотациями
с Unicode и собственным appearance. Экспорт не растрирует страницы и не меняет
исходный файл. Сам просмотрщик также показывает комментарии исходного PDF.
Текстовый слой/поиск по PDF и правка существующего текста в этом шаге не добавлены.
DOCX по-прежнему использует PDF только для фиксированного просмотра.

CSV/TSV открывается таблицей; кнопка чтения сохраняет прежнюю читалку/исходник и
озвучивание. Фильтр таблицы сохраняется при возврате. Доступны разделитель (запятая, точка с запятой,
табуляция, вертикальная черта), первая строка как заголовки, поиск-фильтр,
страницы по 50 записей и правка существующих ячеек/заголовков. Режим исходника
и таблица используют один CodeMirror-документ, историю Undo и механизм сохранения.
Ввод ячейки сразу попадает в черновик; галочка лишь завершает ввод. Фильтр не меняет
набор сохраняемых записей. Парсер хранит точные границы полей: замена касается одной
ячейки, сохраняет остальные лексемы, кавычки и числовую точность. При необходимости
новое значение экранируется. BOM, UTF-8 и окончания строк сохраняются прежним editor
pipeline; другие кодировки и смешанные окончания не нормализуются молча. Ошибка
кавычек оставляет исходник доступным. Структурные изменения строк/столбцов пока
выполняются в исходнике; формулы не вычисляются.

Проверки: `document-tools.test.mjs`, `document-tools.browser.mjs`, прежние
`file-tools.browser.mjs`, `manual-edit.browser.mjs`, `file-preview.browser.mjs`,
`help-content.test.mjs`, web typecheck/build и scoped Biome. Реальные скачанные
байты, BOM/CRLF/многострочные поля, скрытые записи, Undo и восстановление черновика;
PDF с CropBox, UserUnit и поворотами 0/90/180/270, Unicode-комментарии, неизменность исходника
и повторное открытие экспортированной копии. Chromium/WebKit и четыре темы;
проверки не выдаются за использование физического iPad.
[Снимки с описаниями](../polish/05-files/document-tools/README.md).
