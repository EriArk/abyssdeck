# Общий просмотрщик — предложение, 3 октября

Это следующий этап обсуждения после Git. `viewer-study.html` — интерактивный
эскиз компоновки, а не новая реализация просмотрщика и не установленный выпуск.
Код приложения и сервер не изменены. Корпус одобрен владельцем; следующий
вариант уточняет переход просмотра в правку и инструменты всех форматов.

## Уточнение после одобрения

[Полная карта форматов, существующих функций и расширений](../../../docs/FILE_WORKSPACE_TOOLS.md).
Картинки и Markdown — примеры, не ограничение возможностей общего модуля.

В макете карандаш добавляет режимы «Просмотр / Правка» в том же корпусе.
PNG/PDF получают рисование маркером и пером; пометки PDF разделены по страницам.
MD получает заголовок, жирный/курсив, список/задачу, ссылку, код и Undo/Redo.
Пустой текст остаётся пустым; смена режима/файла, свойства, закрытие с возвратом
сохраняют демонстрационный черновик. Сохранение копии показывает назначение,
не записывает файл. Это не production-редактор и не PDF/Markdown-движок;
пока без истинного экспорта, смены формата, серверных квитанций и долговременного
хранения пометок. Сохранение состояния в пределах открытого примера не заменяет
требования к настоящему редактору.

## Что уже общее

`FileViewerDialog` задаёт окно, свойства, контекст и действия. `FilePreview`
и `filePreviewRegistry` выбирают обработчик формата. Есть чтение текста/книг,
изображения, документы, HTML, таблицы/архивы, аудио/видео и технические форматы.
Наличие обработчика само по себе не подтверждает полноту каждого формата.

Сейчас навигация подборки, инструменты формата, инструменты чтения и нижние
действия складываются из разных компонентов. Предложение упорядочивает их
в общем корпусе, сохраняя существующие контроллеры и возможности.

## Предлагаемая конструкция

- Заголовок: имя, короткий источник и оконные кнопки. Перемещение, размер,
  геометрия и док используют существующий механизм; телефон сохраняет свой режим.
- Под заголовком: три группы — файлы подборки, инструменты формата, действия
  с файлом. На телефоне инструменты формата переходят на второй ряд.
- Большой непрерывный экран содержимого. Снизу только короткая строка состояния
  и возврат к исходному сообщению, когда такой источник есть.
- Свойства скрыты по умолчанию. На широком экране — правая панель с существующим
  общим регулятором ширины; на телефоне — раскрываемая панель поверх содержимого.
  В эскизе показаны её открытие/закрытие, перетаскивание ещё не реализовано.
- Переход по файлам и переход по страницам — разные группы. PNG получает масштаб,
  PDF — страницы/масштаб, текст — чтение/исходник/озвучивание. Остальные обработчики
  сохраняются и подключают свои инструменты к тому же месту.
- Рабочий файл редактируется по точному источнику. Для Results/вложений редактируется
  копия. Сохранение и системная отправка остаются существующими общими действиями.

Действия сохранения/отправки/озвучивания в эскизе показывают назначение, ничего
не отправляют и не исполняют. PDF и глава демонстрационные; изображение — сохранённый
снимок реального Git-компонента на проверочном проекте. Это не новый PDF-рендерер.
Настройки Tweak меняют тему корпуса. Стрелки файлов переключают PNG/PDF/MD.

## Проверки

Chromium и WebKit: четыре темы, ширины 780/390, навигация файлов/страниц, свойства,
исходный текст и сохранение демонстрационного черновика при закрытии/возврате.
Снимки с соседними MD в этой папке. Это браузерная проверка эскиза.
Уточнённый вариант также проверен в обоих движках: один корпус, пустой черновик,
Markdown-команда и Undo/Redo, рисунок и отмена/возврат штриха, независимые страницы,
возврат к тексту после другой картинки. Ширины 320/390/780, четыре темы.

Для воспроизведения создать `.local/viewer-study-preview.html` обёрткой `render.py`
из навыка visualize, затем выполнить `node polish/05-files/viewer-study/check.mjs`.

Каркас одобрен; инструменты и переходы уточнены следующим вариантом. При переносе не менять поведение озвучивания,
пагинации, загрузки исходных байтов и сохранения родительского окна.
