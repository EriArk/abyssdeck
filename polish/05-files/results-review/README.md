# Results: текущий экран и направление обсуждения

Исходный экран просмотрен в Chromium/WebKit; код ResultFeed, Results, ResultFilters и ResultSearch изучен. Production Results в этом проходе не менялся.

Наблюдения:

- Простой файл занимает высокую карточку: отдельные участки для заголовка/даты, отрывка, действий, размера и перехода к сообщению.
- «Скачать» и «К сообщению» повторяются крупными элементами у каждого файла; вертикальный расход растёт с количеством результатов.
- Категории стоят в горизонтальной ленте, на телефоне конец скрывается. Служебные «Работа»/«Рассуждения» зависят от клиента и конкурируют с файлами/картинками.
- Иконка папки используется и для обычного файла. Общий счётчик не объясняет состав готовых материалов.
- Поиск уже существует, но это отдельное окно с собственными типом/порядком, списком и просмотром: не нужно разрабатывать поиск повторно.

Предложение для обсуждения:

- Файлы — компактные строки с правильной иконкой типа, названием, размером и временем; отрывок при необходимости раскрывается.
- Изображения — миниатюры с сохранением открытия в существующий общий просмотрщик и листания.
- Вторичные действия — компактные понятные значки с доступными названиями; выбор нескольких, отправка, скачивание и исходное сообщение сохраняются.
- Фильтры/поиск — компактная общая верхняя панель; служебные записи доступны вторично, без потери данных.
- Results остаётся лентой результатов конкретного разговора, а не деревом файлов. Сохраняем категории, прокрутку, точные источники и квитанции.
